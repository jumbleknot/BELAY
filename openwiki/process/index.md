# Files

- [The governing constitution](constitution.md) - BELAY's ratified, versioned constitution, derived from MovieCollectionManager's — the non-negotiable principles (AI assistant constraints, security, TDD), the common stack rules (pnpm, Nx, RTK, dependency pinning, documentation and the doc-impact sweep), the per-layer principles a future project inherits, and the amendment process every spec and plan is checked against.
- [PR batching — split only when a failure would be ambiguous](pull-request-batching.md) - The rule for how many pull requests to open for a set of changes — batch by default and split only when a red build could not be attributed to one change — and why, once a feature ships in several PRs, main stops being a valid baseline for "was this already broken?".
- [Proposal → spec → plan → tasks → implementation lifecycle](spec-driven-development.md) - How an idea becomes shipped work in BELAY — a proposal or design record, then GitHub Spec Kit's numbered spec, plan and tasks, then implementation — which changes need a spec first and which are exempt, the order of the /speckit-* commands, and how to read a feature folder's state.
- [Test authoring conventions — the RED/GREEN task format and what a red test proves](test-authoring-conventions.md) - The rule that every feature test task follows the Verify RED then Verify GREEN checkpoint format, how to get a genuine RED when the behaviour already exists, why watching a test fail proves it sensitive but not correct, and how to decide between fixing the code and fixing the spec.
- [OpenWiki bundle maintenance](wiki-maintenance.md) - How this hand-authored openwiki/ bundle is kept current — the coding session refreshes a derived page in the same PR as its source and records its fingerprint with wiki-refresh.mjs, adds a concept for a new runbook, keeps every directory's index.md and the AGENTS.md index in step, and lists authoritative pages in protected.yaml — and the OKF and governance gates that enforce it in scripts:lint.
